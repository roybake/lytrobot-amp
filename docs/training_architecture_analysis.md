# LYTrobot AMP 训练架构分析

## 一、项目总览

本项目是一个**双足机器人运动技能训练系统**（LYT Biped），基于 MuJoCo 物理引擎 + PyTorch + Warp GPU 加速，训练肌腱驱动的 14 自由度下肢机器人。核心任务分为两大类：

| 训练管线 | 入口脚本 | 说明 |
|---------|---------|------|
| **蹲起训练 (Squat)** | `squat_training/train_stage1.py` / `train_stage2.py` | 双脚着地的对称下蹲动作 |
| **多动作训练 (Multimotion)** | `scripts/train_multimotion.py` | 单策略驱动 6 种地形动作：walk / rough / pit / gap / stair_up / stair_down |

两种训练共享同一套核心算法框架（BPO-AMP），但在奖励函数、运动参考数据和环境配置上有差异。

## 二、核心算法：BPO-AMP

### 2.1 整体架构

```
┌──────────────────────────────────────────────────────────────┐
│                    BPO-AMP 训练循环                            │
│                                                              │
│  ┌──────────┐    ┌──────────────┐    ┌──────────────────┐   │
│  │ 4096 并行 │───▶│  Rollout     │───▶│  PPO/BPO Policy  │   │
│  │ MuJoCo   │    │  采集 24步   │    │  Update (4 epoch)│   │
│  │ Warp环境 │    │  98,304条    │    │  8 minibatch     │   │
│  └──────────┘    │  transition  │    └──────────────────┘   │
│                   └──────────────┘              │             │
│                          │                      ▼             │
│                          │         ┌──────────────────┐      │
│                          │         │  AMP Discriminator│      │
│                          └────────▶│  Update (2次)     │      │
│                                    │  4096样本/次      │      │
│                                    └──────────────────┘      │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 BPO (Bounded Policy Optimization)

BPO 是本项目的关键创新，它**替代了标准 PPO 的 clipped surrogate objective**。核心思想是**用中位值批评家（Median Critic）推导出有界的策略比率目标**，而不是对旧策略比率做简单裁剪。

**BPO 损失函数：**

```
target_ratio = 1 + ε · tanh( (R - V_median) / (2λ) )
policy_loss  = |target_ratio - ratio| · |R - V_new|
```

其中：
- `R` = GAE 回报
- `V_median` = 中位值批评家的预测
- `V_new` = 当前值函数预测
- `λ` = BPO 正则化系数（默认 0.001）
- `ε` = clip 范围（默认 0.2）
- `ratio` = exp(log π_new - log π_old)，即新旧策略比率

**BPO 与标准 PPO 的关键区别：**

| 特性 | 标准 PPO | BPO-AMP |
|------|---------|---------|
| 策略约束 | 裁剪 ratio 到 [1-ε, 1+ε] | 用 tanh 函数推导有界目标 ratio |
| 值函数 | 单一 Critic | 双 Critic：常规 + 中位值（Median） |
| 更新权重 | 固定 clip 范围 | 按 |return - V_new| 自适应加权 |
| 学习率 | 固定或线性衰减 | KL 散度自适应调整 |

### 2.3 AMP (Adversarial Motion Prior) 判别器

AMP 的核心理念是**让策略模仿参考运动数据的"风格"**，而不显式跟踪每个关节角度。

**AMP 观测特征（49维）：**
```
[root_height(1) + root_quat(4) + joint_positions(14) + joint_velocities(14) + foot_positions(12)]
```
所有特征经过 Z-score 归一化（使用参考数据的全局均值和标准差）。

**判别器架构：**
- 输入：49维 AMP 特征
- 网络：256→128 LeakyReLU MLP，输出 1 维 logit
- 奖励：`-log(sigmoid(-logit))`，裁剪到 [0, 5]

**训练细节：**
- 标签平滑 0.20（agent=0.2, reference=0.8）
- 梯度惩罚系数 2.0
- 输入噪声标准差 0.05
- 50% 镜像增强概率
- 每轮更新 2 次，每次 4096 样本

### 2.4 GAE 优势估计

```
δ_t = r_t + γ · V(s_{t+1}) · (1 - terminal) - V(s_t)
A_t = δ_t + γ · λ_GAE · (1 - terminal) · A_{t+1}
```

- γ = 0.99
- λ_GAE = 0.95
- 正确处理 episode timeout（不把 timeout 当作真正的终止状态）

## 三、神经网络架构

```
┌─────────────────────────────────────────────────────┐
│                   Actor-Critic                       │
│                                                     │
│  ┌──────────────┐    ┌──────────────┐               │
│  │    Actor     │    │   Critic     │               │
│  │  256 → 128   │    │  256 → 128   │               │
│  │  ELU → Tanh  │    │  ELU → 线性  │               │
│  │  输出: 14维  │    │  输出: 1维   │               │
│  └──────────────┘    └──────────────┘               │
│                                                     │
│  ┌──────────────┐    ┌──────────────┐               │
│  │  log_std     │    │Median Critic │               │
│  │  (可学习)     │    │  256 → 128   │               │
│  │  范围:       │    │  ELU → 线性  │               │
│  │  [0.05,0.60] │    │  输出: 1维   │               │
│  └──────────────┘    └──────────────┘               │
└─────────────────────────────────────────────────────┘
```

**观测空间组成（以多动作为例）：**

| 模块 | 维度 | 内容 |
|------|------|------|
| 当前状态 | 1+4+6+28+14+3=56 | 根高度+四元数+根速度+关节位置/速度+上一动作+直立/相位 |
| 跟踪目标 | 1+4+6+28+14+12+2=67 | 参考根高度+四元数+速度+关节位置/速度+肌腱目标+足端位置+接触 |
| 技能条件 | 6 | 6维动作 one-hot（多动作模式） |
| **总计** | **129** | |

### 传感器模式（仅 IMU + 肌腱长度）

当使用传感器策略时，观测变为连续 6 帧历史堆叠：
- 每帧：42 维 IMU（加速度计+陀螺仪）+ 14 维肌腱长度 = 56 维
- 6 帧堆叠后：**336 维**
- 不包含关节真值、相位、足端状态、地形标签或目标速度

## 四、奖励函数设计

### 4.1 行走/多动作奖励（约 25 个组成部分）

```
reward = 0.05                                       # 生存奖励
       + 1.40 · pose_track                          # 关节姿态跟踪（加权：膝1.35, 踝1.60）
       + 0.45 · vel_track                           # 关节速度跟踪
       + 0.75 · height                              # 根高度匹配
       + 0.90 · root_orientation                    # 躯干朝向
       + 0.90 · root_vel                            # 根线速度+角速度（0.65+0.35权重）
       + coef_fv · stable_forward_velocity_track    # 前向速度（稳定性门控）
       + coef_fp · stable_forward_progress          # 前向进度
       + 1.25 · foot_pos_track                      # 足端位置跟踪
       + 0.35 · foot_vel_track                      # 摆动足速度
       + 1.00 · stance_foot_track                   # 支撑足水平零速
       + 0.70 · contact_track                       # 接触一致性
       + 0.45 · distal_vel_track                    # 踝关节/趾关节速度
       + 1.20 · symmetry                            # 左右对称（足步幅60%+接触25%+动作15%）
       + 0.35 · ctrl_track                          # 肌腱控制误差
       - 0.040 · ctrl_penalty                       # 动作幅度惩罚
       - 0.100 · action_rate                        # 动作变化率惩罚
       - 0.030 · distal_action                      # 远端动作幅度惩罚
       - 0.120 · distal_action_rate                  # 远端动作变化率惩罚
       - 0.80 · missed_contact                       # 参考支撑但未接触惩罚
```

**稳定性门控（Stability Gating）：**
```
stability = sqrt(clip(root_orientation, 0, 1) × clip(height, 0, 1))
gated_forward_reward = forward_reward × stability
```
这意味着躯干倾斜或高度偏离时，前向速度奖励会被衰减，防止"前冲后倒"获得正奖励。

### 4.2 蹲起奖励

蹲起训练覆盖 `_compute_reward_done` 方法，将步态相位对称改为**双脚平踏对称**：
- 用跨步对称性（stride symmetry）+ 横向对称性（lateral symmetry）替代步态相位对称
- 对称性权重：足部 65% 步幅 + 35% 横向镜像
- 接触奖励占比较高（双脚始终着地）

## 五、训练两阶段课程

### 5.1 Stage 1：模仿学习（无领域随机化）

```
┌─────────────────────────────────────────────┐
│              Stage 1: 模仿学习                │
│                                             │
│  • 30,000 iterations                        │
│  • 4096 并行环境（或 1024）                    │
│  • 无领域随机化                               │
│  • 从参考姿态初始化（motion_reset_prob=0.5）   │
│  • 静止起步概率 0.5（stand_start）            │
│  • 目标速度 1.0 m/s                          │
│  • Actor LR: 3e-4, Disc LR: 3e-5            │
│  • 权重保存间隔: 500 iteration                │
└─────────────────────────────────────────────┘
```

### 5.2 Stage 2：鲁棒性训练（领域随机化）

```
┌───────────────────────────────────────────────────┐
│            Stage 2: 鲁棒性训练                       │
│                                                   │
│  • 从 Stage1 checkpoint 加载权重                    │
│  • 7,500 iterations（或 10,000）                    │
│  • 4096 并行环境                                    │
│  • 领域随机化逐步开启：                               │
│    - 负重质量: 0~3 kg                               │
│    - 身体质量缩放: 0.85~1.15×                        │
│    - 肌腱长度缩放: 0.95~1.05×                        │
│    - 地面摩擦: 0.55~1.40                            │
│    - 重力: 9.75~9.85 m/s²                          │
│    - 随机推力: 0~80 N                               │
│    - 观测噪声 σ=0.02                                │
│    - 动作噪声 σ=0.01                                │
│    - 动作延迟: 2~5 ms                               │
│  • 领域随机化课程：                                   │
│    - 线性模式：在 N 轮内从 0 线性升至 1.0              │
│    - 自适应模式：根据成功率/终止率自动进退              │
│  • Actor LR: 7e-5, Disc LR: 2e-5                   │
└───────────────────────────────────────────────────┘
```

### 5.3 自适应领域随机化课程

```
if 成功率 ≥ 50% AND 下蹲深度成功率 ≥ 30% AND 终止率 ≤ 0.1%:
    scale += 0.025 (promote: 加大随机化)
elif 成功率 < 30% OR 下蹲深度 < 15% OR 终止率 > 0.2%:
    scale -= 0.025 (backoff: 减小随机化)
else:
    scale 保持不变 (hold)
```

## 六、多动作训练地形课程

### 6.1 串联路线机制

```
┌──────────────────────────────────────────────────────────────┐
│              Serial Terrain Course (直线全地形)                │
│                                                              │
│  路线组成: walk → rough → pit → gap → slope_up →              │
│            slope_down → stair_up → stair_down                 │
│                                                              │
│  • 8 种随机排列（--terrain-course-variants 8）                 │
```
